# GitScanner 使用指南

GitScanner 会克隆代码仓库的完整历史记录，遍历每一个独立的 blob，并
报告发现的所有凭据 — 无论是在当前代码树中还是在历史记录的任何位置。
本页是仪表盘的快速使用指南。

## 连接 API

API 地址位于顶部栏；当仪表盘能够连接到 API 时，旁边的指示灯为绿色。
如果您没有运行默认的 `http://localhost:8080`，可将其指向您自己的 API 主机。
API 地址、您的主题设置和语言偏好都会保存在当前浏览器中。

使用右上角的控件可以在**亮色和暗色主题**之间切换，并选择您的**语言**。

## 启动扫描

点击**新建扫描**（左上角或侧边栏）。选择要扫描的目标：

- **代码仓库** — 一个 HTTPS 克隆 URL，例如 `https://github.com/owner/repo`。
- **用户**或**组织** — 该账户拥有的所有代码仓库。勾选*包含 Fork 的代码仓库*
  也会扫描复刻的代码库。

扫描任务会在后台运行。页面将跳转到扫描详情视图，随着代码仓库被逐步处理，
进度条和各项计数器会实时更新。

## 查看结果

**概览**是核心概况：未解决发现项总数、其中严重级别数量、HEAD 中仍有效的凭据数量，
以及按严重程度、提供商和分类状态的详细统计。
每个卡片和图表条目都可以点击跳转到已筛选的发现项列表。

**分析**提供更深入的数据 — 凭据引入的时间线，以及按应用类型和检测规则的分布。

**发现项**是完整且支持筛选的列表。可以按严重程度、提供商、状态或关键词筛选；
筛选条件保存在 URL 中，方便分享或加入书签。每一行显示：

- 凭据所属的严重程度和提供商；
- 掩码预览 — 真实凭据绝不会离开扫描引擎；
- 文件与行号，带有直接跳转至 GitHub 文件的链接；
- 引入该凭据的提交记录、作者和日期；
- **暴露情况** — `在 HEAD` 表示其仍存在于当前代码树；`历史记录`
  表示已从当前树中移除但仍可通过克隆仓库查到；
- 当活动凭据验证确认该密钥仍然可用时，会显示 **有效 — 立即轮换** 徽章。

在处理发现项时，使用每行末尾的菜单将其标记为**已轮换**、**误报**或**已忽略**。

## 代码仓库与未映射模式

**代码仓库**根据未解决暴露项对每个扫描过的仓库进行排名，并按严重程度细分。
**未映射**是尚未被明确规则认领的高熵机密待处理列表，按特征模式聚集 — 
高频出现的模式往往代表值得为其编写专用规则的提供商。

## 活动凭据验证

当管理员为其扫描目标启用了该功能时，GitScanner 会针对每个发现项执行一次
只读身份认证调用，以确认密钥是否依然有效及其所属账户。
被确认仍然有效的密钥应优先立即轮换。该功能默认关闭，且绝不会遍历账户内容。
