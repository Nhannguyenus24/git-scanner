# GitScanner 使用指南

GitScanner 会克隆代码仓库的完整历史记录，对每一个独立的文件版本（blob）只读取一次，
并报告发现的凭据 — 无论是在当前代码树中还是在历史记录的任何位置。三年前删除的密钥，
任何克隆该仓库的人依然可以读到，因此在被吊销之前，它仍然是一次泄露。

本指南逐页介绍仪表盘的用法。简要流程如下：

1. 确认顶部栏中 API 地址旁的指示灯为绿色。
2. 点击**新建扫描**，指定一个代码仓库、用户或组织。
3. 在扫描页面上关注进度，直到扫描完成。
4. 逐项处理**发现项**：轮换仍然有效的凭据，标记并非泄露的条目。
5. 在**代码仓库**中发送披露邮件，告知仓库所有者。

## 界面

### 顶部栏

- **API 地址** — 屏幕上所有数据的来源服务器。旁边的指示灯在检查时为灰色，
  API 有响应时为绿色，无法连接时为红色。如果您没有运行默认的
  `http://localhost:8080`，请输入您自己的主机地址；它会保存在当前浏览器中。
- **命令框** — 打开命令面板（见下文）。
- **帮助** — 即本页面。
- **亮色 / 暗色** — 在亮色和暗色主题之间切换。
- **语言** — English、Tiếng Việt、Italiano、中文、Español、Deutsch 和
  Français。所有内容（包括本指南）都会随之切换。

### 侧边栏

每个页面都只需一次点击即可到达。其中三个条目带有实时计数：**发现项**
（未解决的发现项）、**扫描**（仍在运行的扫描）和**未映射**（等待提供商规则的模式）。
使用侧边栏底部的箭头或 `Ctrl+[`（Mac 上为 `⌘[`）可将侧边栏折叠为仅显示图标。
在手机上，侧边栏会变成底部栏；不常用的页面位于**更多**之下。

### 键盘

- `Ctrl+K` / `⌘K` — 在任意位置打开或关闭命令面板。
- `/` — 打开命令面板。
- `N` — 开始新扫描。
- `Ctrl+[` / `⌘[` — 折叠或展开侧边栏。
- `Esc` — 关闭对话框、抽屉或面板。

在文本框中输入时，`N` 和 `/` 会被忽略，因此它们不会吞掉本应输入到筛选框中的按键。

### 命令面板

一个框即可完成仪表盘中所有可通过键盘执行的操作。输入文字以缩小列表范围，
使用 `↑` `↓`（或 `Ctrl+N` / `Ctrl+P`）移动，按 `Enter` 执行。它提供：

- **操作** — 开始新扫描；导出当前视图。
- **前往** — 所有页面。
- **筛选器** — 发现项预设和您保存的筛选，一步应用。
- **外观** — 亮色或暗色、跟随系统、各个主题、密度、动效、侧边栏以及重置。
- **语言** — 切换界面语言。

输入的其他任何内容都会变成**在发现项中搜索“…”**，它会以该文本作为搜索筛选条件打开发现项页面。
命令面板刻意不保留历史记录：一个会记忆输入的搜索框，就可能成为粘贴进去的凭据的落脚之处。

当服务器配置了 Claude API 密钥时，多于一个词的查询还会提供**问 Claude：“…”**。
它会把*acme 组织中仍在 HEAD 的严重 AWS 密钥*这样的句子解读为发现项的筛选条件，
用这些条件打开发现项页面，并说明它是如何理解这个问题的，方便您修正。
发送给 Claude 的只有问题本身和筛选值列表 — 绝不会发送任何发现项 — 而看起来包含凭据的问题
会在发送任何内容之前被拒绝。

### 入门导览

仪表盘首次打开时会提供一个七步的入门导览。您可以随时跳过；之后可在
**设置 → 入门导览**中重新播放。

## 启动扫描

点击**新建扫描**（侧边栏、概览或扫描页面，或按 `N`）。选择一个目标：

- **代码仓库** — 一个 HTTPS 克隆 URL，例如
  `https://github.com/owner/repo`。SSH URL 以及包含用户名或令牌的 URL
  会被拒绝。
- **用户** — 某个 GitHub 用户拥有的所有代码仓库。用户名由字母、数字和连字符组成，
  长度为 1–39 个字符。
- **组织** — 某个 GitHub 组织拥有的所有代码仓库。
- **随机** — 随机抽样的公开代码仓库，仅用于检测测试。输入数量，或勾选
  **持续运行**，持续抽样直到您暂停或取消。

对于用户、组织和随机扫描，勾选**包含 Fork 的代码仓库**即可同时扫描复刻仓库；
默认会跳过它们，因为复刻仓库的内容大多与其父仓库重复。

点击**开始扫描**或按 `Enter`。扫描会在后台排队，仪表盘随即打开其详情页面。

## 跟踪扫描

### 扫描列表

**扫描**列出 API 接收的所有任务，最新的排在最前。可在
**全部**、**运行中**和**已完成**之间切换。每一行显示状态、目标、进度、已读取的 blob 数、
新发现项、开始时间和运行时长。点击某一行即可打开；行末的图标用于重新扫描或删除已结束的任务。

任务处于以下六种状态之一：**排队中**、**运行中**、**已暂停**、
**已完成**、**失败**或**已取消**。

### 扫描详情

页眉显示目标、扫描类型、提交时间以及已运行的时长。按钮会随状态变化：

- **暂停**（运行中）— worker 不再领取新的代码仓库；已经发现的内容不会丢失。
  **继续**会从停止处接着运行。
- **取消**（任何未结束的任务）— 永久停止该任务。
- **重新扫描**（已结束）— 将同一目标作为新任务再次排队。
- **删除**（已结束）— 删除该任务**及其记录的所有发现项**。
  此操作无法撤消。

页眉下方：

- **计数器** — 已完成的代码仓库数与总数、已扫描的 blob 数，以及新发现项
  （由此任务首次发现）。
- **进度与剩余时间** — 当有足够数据时会显示估算值；在此之前，以计数器为准。
- **阶段** — 发现仓库 → 扫描仓库（克隆、遍历历史、检测）→ 归类提供商 → 汇总分析。
- **流水线** — 每个代码仓库一个点，停在其 worker 最近报告的步骤（克隆、读取历史、
  追溯提交、验证、保存），并随着下一步被报告而前移；已完成的代码仓库落入右侧的收纳区。
  橙色表示目前已有候选匹配，红色表示某次尝试失败，灰色表示已跳过。
- **实时活动** — 扫描运行期间从 worker 实时推送。
- **摘要** — 任务完成时显示：在多少个代码仓库中发现了多少项、其中多少项为高或严重级别、
  多少项仍可从默认分支获取，以及哪些代码仓库受到影响。
- **本次扫描记录的发现项** — 发现项列表本身，并附有在发现项页面中打开的链接。

### 实时活动

实时面板显示每个 worker 当前正在做什么。其状态为
**连接中**、**实时**、**重新连接中**、**已结束**或**不可用**；如果服务器不支持流式推送，
上方的计数器仍会每隔几秒刷新一次。

- **发现** — 对于用户和组织扫描，逐页列出该账户的代码仓库。
  *正在等待 GitHub 速率限制* 只是暂停，并非失败。
- **进行中** — 每个代码仓库及其当前所处的步骤：**克隆**（bare：
  仅分支和标签）、**读取历史**（每个独立的文件版本，并实时显示候选匹配数）、
  **追溯提交**（将每个匹配追溯到引入它的提交）、**验证**（实时验证，如已启用）以及
  **保存**。
- **刚完成** — 刚刚完成的代码仓库，附带其新发现项、已读取的 blob 数和耗时。
- **活动日志** — 完整的事件流；**再显示**可将其展开。

某次尝试失败的代码仓库会自动重试，并显示*第 2 次尝试*、*第 3 次尝试*…
最后一次尝试仍失败的代码仓库会被**跳过**；任务的其余部分继续进行。

### 为什么扫描可能没有新发现

每个凭据只记录一次，归属于首次发现它的扫描。再次扫描同一个代码仓库会找到同样的密钥，
但不会记录*新*发现项 — 它们仍归属于先前的扫描。打开按该代码仓库筛选的**发现项**
即可看到全部内容。

## 概览

核心概况页面，每十秒刷新一次（**实时**标记会显示刷新间隔）。

- **安全态势** — 满分 100 的评分。点击**如何计算**可查看每一项扣分（见下文）。
- **关键计数** — 未解决发现项、严重、HEAD 中仍有效、暴露的代码仓库、
  正在运行的扫描、未映射模式。
- **按严重程度分布（未解决）**、**按提供商分布（未解决）**、**分类状态** — 各类细分统计。
  每个卡片和图表条目都是跳转到已筛选发现项列表的链接。
- **近期动态** — 完成或失败的扫描、新发现项、已发送的披露。
- **最近扫描** — 最新的任务及其进度。

### 布局

**布局**可在四种排列方式之间切换：**全部**、**每日分诊**
（计数与细分，不含评分）、**管理层概览**（评分、关键数字、近期变化）和
**安全运营**（优先显示动态与正在运行的扫描）。**自定义**允许您用箭头将面板上移或下移，
用眼睛图标隐藏面板，并从下方列表中恢复已隐藏的面板。布局保存在当前浏览器中。

### 安全态势评分如何计算

评分从 100 开始，按各项因素扣分。每项扣分都有上限并逐渐饱和，因此最初的几个发现项
扣分最多，且任何单一因素都不会失控：

- **严重发现项** — 最多扣 30 分。
- **可从 HEAD 获取** — 最多扣 25 分。这是最强烈的信号：今天克隆默认分支的任何人
  都能拿到该凭据。
- **高危发现项** — 最多扣 15 分。
- **暴露的仓库** — 最多扣 15 分，按存在未解决发现项的已扫描代码仓库所占比例计算。
- **未处理占比** — 最多扣 10 分，按仍未解决的发现项所占比例计算。
  已关闭的发现项不扣分。
- **未通知所有者** — 最多扣 5 分，针对尚未发送披露的暴露代码仓库。

85 分及以上为**良好**，65–84 为**需改进**，40–64 为**已暴露**，低于 40 为
**严重**。尚未扫描任何内容时不显示评分，而不是显示一个具有误导性的 100。
评分在浏览器中根据服务器的全库计数计算得出，绝不基于某一页发现项。

## 发现项

所有已记录凭据的完整列表，每页 50 行。

### 筛选

- **搜索** — 路径、规则、提供商或代码仓库。
- **严重程度**、**提供商**、**状态**（未解决、已轮换、误报、
  已忽略）。
- **暴露面** — 在 HEAD、仅历史记录或已确认有效。
- **排序** — 默认、最近检测、最旧提交或严重度。
- **单个仓库** / 扫描 — 从某个代码仓库或扫描跳转过来时以标签形式出现；
  移除它即可查看全部内容。

筛选条件保存在 URL 中，因此筛选后的视图可以加入书签、分享，或在刷新后重新打开。
**清除筛选**可将其重置。

暴露面和排序在浏览器中计算。启用其中任意一项时，页面会从服务器加载最多 500 个发现项
并在其中进一步筛选；如果实际数量更多，页面会在表格上方注明，而不是显示一个具有误导性的总数。

### 预设与已保存的筛选

**筛选器**菜单提供现成的视图：

- **严重且未处理** — 优先轮换这些凭据。
- **可从 HEAD 获取** — 今天克隆的人都能读到。
- **已确认有效** — 探测收到了有效响应。
- **未归属** — 没有任何提供商规则认领。
- **最近发现** — 最新检测优先。
- **悬而未决最久** — 最旧的提交优先。

**保存当前筛选**会以一个名称保存您设置的筛选条件；可在同一菜单中重命名或删除，
命令面板中也会提供。已保存的筛选只存在于当前浏览器中，且只保存筛选字段 —
绝不保存看起来像是粘贴进来的机密的搜索文本。

### 解读一行

- **严重程度**以及凭据所属的**提供商**（或
  *未映射*）。
- **凭据** — 掩码预览。除非您明确开启了取消遮蔽（见设置），否则真实值绝不会离开扫描引擎。
- **代码仓库**和**位置** — 文件与行号，链接到 GitHub 上的文件。
- **暴露情况** — `在 HEAD` 表示其仍存在于当前代码树中；`历史记录`
  表示已被移除但仍可通过克隆获取。*提交未知 — 请重新扫描以归因*
  表示尚未追溯到引入它的提交；重新扫描即可补全。
- **有效 — 立即轮换** — 实时验证确认该密钥仍然可用。
- **状态**和**检测时间**。

行末的菜单可将发现项标记为**未解决**、**已轮换**、**误报**
或**已忽略**。

### 发现项详情

点击某一行即可打开详情抽屉。其地址会写入 URL，因此
**复制链接**可让同事看到相同的视图；**复制引用信息**会复制一段用于工单的简短引用。
抽屉中显示：

- **凭证** — 掩码预览、类别和有效性。当该值已为不遮蔽的所有者保存且遮蔽已关闭时，
  **显示**会将其展示出来，并标记为**未遮蔽**。
- **配额与限制** — 提供商在有效性检查时报告的内容：剩余请求数或令牌数、权限范围、
  国家、货币。这是扫描时的快照。
- **为何被检测到** — 规则、所归属的提供商、长度和字符集、附近的变量或主机名，
  以及暴露情况。说明仅基于形态、长度和上下文，绝不涉及凭据值本身。
- **位置** — 文件、提交、作者和提交日期，并附有跳转到 GitHub 上对应行的链接。
- **时间线** — 提交、检测、探测以及处理决定。
- **处置步骤** — 按顺序排列的修复步骤：在提供商处吊销并重新签发、检查其审计日志、
  从 HEAD 中移除该值、决定是否重写历史，以及添加 pre-commit 机密检查。
- **同一仓库**和**同一提供商** — 相关的发现项，一键可达。
- **元数据** — 引擎记录的其他所有信息。

### 批量处理

勾选行首的复选框，或勾选表头的复选框以选中本页所有行。底部会出现一个栏，
显示所选数量和四种状态。**已轮换**和**误报**会先要求确认，因为每一项都是对外部世界的断言 —
密钥已被吊销、匹配是错误的 — 而在批量操作中，正是这种断言可能悄无声息地关闭一次真实的泄露。
未解决和已忽略会立即生效。**导出所选**只导出勾选的行。

### 导出

**导出**会写出当前已加载的发现项，并在文件中记录生成它们的筛选条件：

- **发现项（CSV）** — 每项发现一行，便于表格处理。
- **发现项（JSON）** — 结构化数据，便于脚本处理。
- **事件报告** — Markdown，按代码仓库分组。
- **管理层摘要** — 一页纸，不含表格。

导出文件只包含掩码预览；明文凭据在任何格式下都绝不会写入文件。

## 代码仓库

所有已扫描的代码仓库，按其未解决暴露的严重程度排名。

- **按所有者/名称筛选**，以及**仅显示有未解决发现项的仓库**。
- **排序方式**：风险、未处理发现数、最近扫描时间或名称。
- 列：类型、各严重级别的未解决数量、未解决 / 总计、**风险**、**下一步**、
  **已通知**和上次扫描时间。
- 点击某个代码仓库即可打开其发现项。

**风险**的取值范围为 0（没有未解决项）到 100。未解决发现项按严重程度加权 —
一个严重级别相当于十个低级别 — 且总分会逐渐饱和，因此只有一个严重发现项的代码仓库
排名就已经很靠前。分档：低、中（25+）、高（50+）、严重（75+）。
将鼠标悬停其上可查看背后的计数。

**下一步**指出最值得做的一件事：*轮换严重级别的密钥*、*通知所有者*、*披露已排队*、
*披露失败——重试*、*复核剩余发现项*或*无未处理项*。

### 通知所有者

顶部的**披露邮件**标签显示邮件功能是否开启；它链接到设置页面。邮件开启时，
某一行上的**通知**会向代码仓库所有者排队发送一封披露邮件，列出其发现项及掩码预览。
随后**已通知**列会显示*发送中*、*已发送*、*失败*或*已退订*。

### 时光机

某一行上的时钟图标（或在按单个代码仓库筛选的发现项页面中的**时光机**标签）
会按提交逐个回放该代码仓库的暴露过程。每个含有凭据的文件占一条泳道；菱形标记引入每个密钥的提交，
并从那里引出一条线一直延伸到今天 — 密钥仍在 HEAD 时为实线，被移除后逐渐淡出。

拖动滑块、用上一步和下一步按钮逐步前进，或按播放从第一次泄露开始向前推进。
每一步，页面都会显示截至当时已提交了多少个凭据、其中多少个今天仍在 HEAD，并提醒它们全部仍可被克隆。
下方按从新到旧列出引入凭据的提交，附有作者、日期以及指向每个发现项的链接。

扫描知道密钥是何时提交的，但不知道它何时被删除，因此已移除密钥的线会逐渐淡出，
而不是终止于一个编造的日期。尚无提交日期的发现项会在列表下方计数；重新扫描即可将其定位。

## 密钥扩散

出现在多个代码仓库中的凭据。发现项在每个代码仓库中只记录一次，因此同一个密钥出现在多处时，
只有在这里才能看到 — 各个副本通过指纹连接在一起。

- **共享密钥**、**跨所有者**（出现在不同所有者仓库中的密钥）、**在 HEAD 中仍未处理**，
  以及受影响的**仓库 / 所有者**。当共享密钥多于图中绘制的数量时，第一张卡片会说明绘制了多少个。
- **出现于** — 显示出现在 2、3、5 或 10 个及以上代码仓库中的密钥。
- **关系图** — 每个密钥一个菱形，按严重程度着色、按扩散范围决定大小；每个代码仓库一个圆形；
  拥有两个或以上代码仓库的所有者各一个方形。红线表示仍在 HEAD 的副本，虚线表示已处理的副本。
  鼠标悬停可高亮某个密钥的相邻节点。
- 旁边的**列表**包含同样的密钥，供键盘和屏幕阅读器使用。在任意一处选中某个密钥，
  都会显示它所在的代码仓库，每个都链接到对应的发现项。

一次轮换即可修复所有副本，因此在确认后，密钥详情可以一次性**将所有副本标记**为*已轮换*或*误报*。
一个被粘贴到许多互不相关的所有者仓库中的值，通常是通用检测误当成密钥的样板内容 —
框架类名、教程中的示例密钥 — 而这个视图是发现它们最快的方式。

## 未映射

尚未被任何具名提供商规则认领的高熵机密待处理列表，按形态聚集。每一行显示一个
**推测名称**（取自最近的变量或键名 — 有时只是附近的一个词）、一个掩码**样本**、
**结构特征**（长度和字符集）、发现时所处的**上下文**、**出现次数**、
其状态以及最后出现时间。反复出现的形态，往往代表值得为其编写规则的提供商。
此类发现项在被规则认领之前显示为*未映射*；一旦有规则认领，下一次扫描会重新归属它们。

## 提供商

GitScanner 能够检测并归属的所有提供商，按类别分组（AI、云、数据、支付、消息、
DevOps、开发工具、其他），并显示每个提供商的规则数量。点击某个提供商可查看：

- **为什么是该严重程度** — 严重表示完全控制；高表示广泛的 API 访问权限；
  中表示范围较窄或限定于主机的访问权限；低表示可识别账户但无法对其执行操作。
- **泄露后他人能做什么** — 该类别的影响。
- **密钥的样子以及如何被检测**，每条规则一张卡片：
  - *自有前缀* — 值以该提供商的前缀开头，这本身就是证据；
  - *配置名* — 本身没有特定形态的值，仅当它被赋给以该提供商命名的配置项时才会报告；
  - *连接 URL* — 内含凭据的 URL；仅指向 localhost 或 compose 服务的 URL
    会被视为开发配置并丢弃；
  - *PEM 块* — 从 BEGIN 到 END 的私钥；
  - *仅凭结构* — 固定长度、分隔符或标记，刻意保持很窄的范围。
  每张卡片可以显示密钥结构、模式、文件中必须包含的文本，以及附近必须出现的词语。
- **匹配之后** — 占位符（`your-…-key`、`xxxx`、`changeme`）、
  文档和沙箱密钥以及测试夹具会被丢弃；保留下来的内容只以指纹和掩码预览的形式存储。

提供商显示其最严重的规则。对于每个发现项，如果泄露仍可从 HEAD 获取，严重程度会提升一级；
对于云和支付提供商会再提升一级，最高至严重。

## 分析

对迄今为止所有扫描内容的总体解读：

- **发现项**和**代码仓库** — 总数、未解决数、暴露数 / 已扫描数。
- **泄露日历** — 每次显示一年，每天一个方块，颜色深浅表示当天提交的凭据数量，
  含严重级别凭据的日子会加上边框。在右上角选择年份。日期按 UTC 计算：
  未记录作者所在时区，因此一个方块可能对应作者当地的前一天或后一天。
- **泄露引入时间线** — 按凭据提交月份划分的发现项。
- **按严重程度分布（未解决）**、**按提供商分布（未解决）**（已知提供商及未映射汇总）、
  **按应用类型**、**分类状态**。
- **检测规则** — 哪些规则触发最频繁。
- **活动凭据验证** — 有效、已撤销、无探测器、检查失败。
- **披露邮件** — 已联系的代码仓库，以及尚未通知的暴露代码仓库。
- **暴露最严重的仓库** — 采用与代码仓库页面相同的风险评分。
- **悬而未决最久** — 按提交日期排列的未解决发现项。

所有数字均为全时段统计；没有日期范围，因为 API 不提供该功能。页面顶部的筛选条件
会作用于本页打开的发现项链接。

## 设置

### 外观

仅保存在本浏览器中。

- **主题** — 纸张（陈旧纸张、墨绿与牛血红）、午夜（近乎纯黑的终端风、荧光绿）、
  海洋（藏青、青色与蓝色）、信号（石墨色，只有告警带颜色）、极简（朴素的企业风格）。
- **浅色或深色** — 浅色、深色，或选择系统以跟随您的操作系统。
- **密度** — 紧凑可在一屏显示更多行。
- **动效** — 减弱会关闭动画。
- **默认折叠侧边栏**。
- **重置外观** — 恢复默认设置。

### 入门导览

**重新播放导览**会再次打开入门导览。

### 浏览器通知

开启此项并获得浏览器授权后，打开着的仪表盘（后台标签页即可）会在它所关注的扫描完成、
以及有更多密钥被确认为有效时通知您；点击通知会打开该扫描或有效密钥列表。
当您正在查看仪表盘时，同样的消息会改为以页面内提示的形式出现。所有仪表盘标签页都关闭后，
不会再发送任何通知。仅保存在本浏览器中。

### 安装仪表盘

可以通过浏览器地址栏将仪表盘安装为应用（在手机上则使用*添加到主屏幕*）。
安装后它会在独立窗口中打开，其外壳无需网络即可加载；数据仍然来自 API，且从不保存在浏览器缓存中。

### 披露邮件

总开关。开启时，通知会向代码仓库所有者发送披露邮件。关闭时，不会发送任何邮件，
已排队的邮件也会被丢弃。目前尚不支持按严重程度或摘要汇总的偏好设置。

### 安全遮蔽与不遮蔽的所有者

**开**（默认）：所有凭据均以遮蔽形式显示。**关**：在**不遮蔽的所有者**中列出的所有者，
其代码仓库中发现的凭据会完整显示，供测试使用；其他所有人仍保持遮蔽，邮件和导出文件
始终为遮蔽形式。

- 只添加您自己拥有的 GitHub 用户或组织。
- 凭据值从下一次扫描起以加密形式保存 — 重新扫描某个所有者的代码仓库，
  才能以未遮蔽形式查看已有的发现项。
- 移除某个所有者会删除为其保存的所有内容。
- 如果服务器没有配置 `SECRET_SEAL_KEY`，则取消遮蔽不可用，也绝不会保存任何内容。
  使用 `openssl rand -hex 32` 生成一个密钥，将其添加到
  `.env.local` 并重启。

遮蔽关闭期间，页面上会一直显示红色警告：任何能够打开此仪表盘的人都能看到所列所有者的完整凭据。

## 活动凭据验证

当管理员为其自己的扫描目标启用该功能（`PROBE_SECRETS`）时，
GitScanner 会针对每个发现项执行一次只读身份认证调用，以确认密钥是否依然有效及其所属账户：

- **有效 — 立即轮换** — 提供商接受了该凭据。请优先轮换它。
- **已撤销** — 提供商拒绝了该凭据；已被轮换或撤销。
- **无探测器** — 该提供商没有对应的检查。
- **检查失败** — 速率限制或网络原因；请稍后重新扫描。

该功能默认关闭，绝不会遍历账户内容，其配额与限制读数会显示在发现项详情抽屉中。

## 严重程度

- **严重** — 完全控制：转移资金、接管账户、读取其保护的所有内容。
- **高** — 以该账户身份进行广泛的 API 访问。
- **中** — 范围较窄或限定于主机的访问权限：一个频道、一个 webhook、
  一台同样需要可访问的服务器。
- **低** — 可识别账户但无法对其执行操作，例如测试模式密钥。仍然值得轮换。

## 故障排查

- **“无法连接到 API”** — 检查顶部栏中的地址以及服务是否已启动；
  API 有响应时指示灯会变为绿色。
- **扫描停留在 0%** — 打开该扫描并查看实时活动。*正在等待 GitHub 速率限制*
  会自行恢复；完全没有活动则说明 worker 没有在运行。
- **重新扫描没有新发现** — 这些发现项属于先前的扫描；请改为按该代码仓库筛选发现项。
- **提交未知** — 重新扫描该代码仓库以完成归因。
- **通知按钮为灰色** — 在设置中开启披露邮件。
- **抽屉中没有显示按钮** — 遮蔽处于开启状态、该所有者不在取消遮蔽列表中、
  服务器没有配置 `SECRET_SEAL_KEY`，或在添加该所有者后没有重新扫描代码仓库。
- **列表提示只在 500 个发现项中进一步筛选** — 收窄服务器端筛选条件（严重程度、
  提供商、状态、代码仓库），使该窗口能够覆盖全部内容。
- **命令面板中没有“问 Claude”** — 服务器未配置 `ANTHROPIC_API_KEY`，
  或查询只有一个词（那是普通搜索）。
- **问 Claude 拒绝了问题** — 问题中含有形似凭据的内容；去掉该值后换个说法。
- **收不到浏览器通知** — 在浏览器中检查本网站的通知权限；已被阻止的网站无法从页面内再次请求授权。
- **结果过时** — 删除任务或清空数据会移除其发现项；重新扫描即可恢复。

GitScanner 仅供经授权的安全测试使用。只扫描您拥有或获准测试的内容，
并将发现的问题告知所有者。
